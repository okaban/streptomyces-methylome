作成 2026-09-28 ／ 手順書 C の実行用。BioProject `PRJNA1533939` と
Zenodo DOI `10.5281/zenodo.22877588` は取得済みなので、残るのは
**BioSample 9 件**と **SRA run 18 件**の登録、そして 14.31 GB の転送です。

アップロードする表は再生成済みで、**中身を編集する必要はありません**。

## 0. 今回直した 4 点（うち 2 点は必須項目の欠落で、前回の表のままでは弾かれます）

| 箇所 | 前回 | 今回 | 理由 |
|---|---|---|---|
| BioSample に `*sample_type` が無い | 欠落 | `cell culture` | package **Microbe 1.0 の必須項目**。NCBI のパッケージ定義（`?format=xml`）で `use="mandatory"` を確認 |
| BioSample に `bioproject_accession` 欄が無い | 欠落 | `PRJNA1533939` | 表に入れておけば、ポータル側の紐付けミスが起きない |
| SRA 表に `assembly` 欄が無い | 欠落 | `GCF_000203835.1` | **aligned data（BAM）では必須**。NCBI の登録済みアセンブリなので fasta 添付は不要 |
| SRA 表に `file_size_gb` という余分な列 | あった | 削除 | 公式テンプレートに無い列。サイズは `upload_manifest.tsv` に移動 |

列名と列順は NCBI 公式テンプレート（`SRA_metadata.xlsx` の `SRA_data` シート、
BioSample は Microbe 1.0 のパッケージ定義）に一致させてあります。
統制語彙（`OTHER` / `RNA-Seq` / `Inverse rRNA` / `OXFORD_NANOPORE` / `MinION` /
`Illumina NovaSeq X Plus`）も公式リストと照合済み、全て有効です。

あわせて確認した事項:

- ONT BAM 9 本の md5 を**本日再計算し、`ont_bam_md5.tsv` と 9/9 一致**。
  Illumina FASTQ 18 本は受託先 `md5.txt` と 18/18 一致（2026-09-23 時点の記録）。
- 3-2 と 3-4 の正準 BAM は `_mapped.bam`（`reanalysis_260224/*_new_aligned.bam`
  は追加分だけの中間ファイル）。`reanalysis_merge_pipeline.sh` で確認。
  この 2 件だけ design description に「追加フローセル分をマージ済み」と明記しました。
- 27 ファイルすべて所定のパスに存在。合計 14.31 GB。

## 2. BioSample 提出（9 件）— 入力する箇所

<https://submit.ncbi.nlm.nih.gov/subs/biosample/> → New submission

| 画面 | 入力する箇所 |
|---|---|
| Submitter | 氏名・メール・所属（アカウントから自動入力。**BioProject 提出時と同一にする**） |
| General Information | 「Batch/Multiple BioSamples」を選ぶ／リリース日は **BioProject と同じ扱い**にする（"Release on specified date or upon publication, whichever is first" ＋ **2027-12-31**） |
| Sample Type | パッケージ **Microbe; version 1.0** を選択（他は選ばない） |
| Attributes | 「Upload a file using Excel or text format (tab-delimited)」→ `biosample_attributes.tsv` |
| Overview → Submit | 内容確認して送信 |

**注意**

- リリース日を BioProject（2027-12-31 / 公開時のいずれか早い方）と揃えてください。
  片方だけ即時公開になると、査読前にデータが出ます。
- 列名の `*` は公式テンプレートの表記です。もしポータルが列名で警告を出したら、
  Sample Type 画面から公式テンプレートをダウンロードし、`biosample_attributes.tsv`
  の値列をそのまま貼り付けてください（属性名は同一です）。
- 数分〜数時間で **SAMN********** が 9 件返ります。`accession_record.tsv` に控えてください。

## 3. SRA 提出（18 run）— 入力する箇所

<https://submit.ncbi.nlm.nih.gov/subs/sra/> → New submission

**BioSample の accession が返ってから**始めてください。

| 画面 | 入力する箇所 |
|---|---|
| Submitter | 同上 |
| General Information | BioProject: **既存のものを選択 → `PRJNA1533939`**／BioSample: **既存のものを選択**（登録した 9 件）／リリース日は BioSample と同じ |
| SRA Metadata | 「Upload a file」→ `sra_metadata.tsv` |
| Files | 転送方法を選ぶ（下の §4）。画面に出る **preload フォルダ名**と **Aspera 鍵 / FTP パスワード**をコピーしておく |
| Overview → Submit | 転送完了後に送信 |

**注意**

- `sra_metadata.tsv` の 1 列目は `sample_name` です。BioSample を同一アカウントで
  登録していれば名前で照合されます。もしポータルが accession を要求したら、
  1 列目の列名を `sample_accession` に変え、`accession_record.tsv` の
  `biosample_accession` 列（SAMN…）を貼り替えてください。
- **pod5 の行は入れません。** SRA は POD5 を受け付けない旨の回答を 2026-09-22 に
  受領済みです。生シグナルは Zenodo 側で扱います（容量上限の引き上げ申請が必要）。

## 4. ファイル転送（14.31 GB）

Files 画面に出る preload フォルダ（`uploads/<メール>_<英数字>/<フォルダ名>`）宛に、
**2 回に分けて**送ります。ファイルは別のディレクトリにあるので、一時コピーは作らず
ファイル一覧を渡す方式です。

Aspera（推奨）:

```bash
cd /Users/okaban/bioinfo/rna-seq
ASCP=~/Applications/Aspera\ Connect.app/Contents/Resources/ascp   # 環境に合わせる
KEY=~/Downloads/aspera.openssh                                    # Files 画面から入手
DEST=subasp@upload.ncbi.nlm.nih.gov:uploads/<メール>_<英数字>/<フォルダ名>

"$ASCP" -i "$KEY" -QT -l 300m -k1 -d --file-list=deposition/upload_list_ont.txt      "$DEST"
"$ASCP" -i "$KEY" -QT -l 300m -k1 -d --file-list=deposition/upload_list_illumina.txt "$DEST"
```

FTP の場合は `ftp-private.ncbi.nlm.nih.gov` に Files 画面のアカウント／パスワードで
ログインし、`cd uploads/...` → `mkdir <フォルダ名>` → `mput` で 27 本送ります。

**転送後**: ポータルが表示する md5 と `upload_manifest.tsv` の `md5` 列を照合してください。
27/27 一致して初めて ONT BAM の md5 が外部検証されたことになります
（Illumina は受託先の値と既に一致済み、ONT は手元計算のみでした）。

## 6. 判断が要る箇所（既定のままでも提出できます）

1. **ONT run の `library_strategy`** — 現在 `OTHER`。ネイティブ DNA のショットガンなので
   `WGS` でも通り、そちらの方が SRA 内で見つけてもらいやすくなります。
   修飾検出が主目的である点は design description に書いてあるので、どちらでも齟齬はありません。
   変える場合は `build_submission_metadata.py` の該当行を直して再生成します。
2. **`sample_type`** — `cell culture`（R5 液体培養の純粋培養として）。
   NCBI 側は自由記述で、`whole organism` を使う例もあります。
3. **`isolate` / `host` の "not applicable"** — 自由生活性の菌なので明示的にそう書いています。
   空欄でも通りますが、キュレータからの問い合わせを避けるために入れてあります。
   任意項目のうち全て "not applicable" だった `lat_lon` と `culture_collection` は列ごと削除しました。
